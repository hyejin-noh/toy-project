# 항목의 수명과 날짜 관계

## Decisions

- 항목은 특정 날짜에 묶이지 않습니다. 열린 항목은 완료할 때까지 오늘 목록에 그대로 남습니다.
- 이월은 별도의 동작이 아닙니다. 날짜가 바뀔 때 항목을 복사하거나 옮기는 처리를 두지 않습니다.
- 날짜는 항목에 붙는 것이 아니라 항목에 쌓이는 기록(언제 올라왔는지, 언제 완료했는지, 이후 날짜별 소요시간)에 붙습니다.
- 목록은 오늘 올라온 항목과 이전부터 남은 항목을 구분해 보여주고, 남은 항목에는 며칠째 남았는지를 표시합니다.

## Boundaries

- 완료한 항목을 화면에서 언제 감출지는 이 계약이 정하지 않습니다. 화면 표시 규칙은 각 작업 단위에서 정합니다.
- 완료한 항목의 기록 자체는 지우지 않습니다. 화면에서 보이지 않는 것과 기록이 사라지는 것은 다릅니다.

## Why

날짜별 목록을 따로 보관하면 날짜 전환 시점, 같은 항목의 중복, 과거 목록의 수정 가능 여부를 모두 정해야 합니다. 혼자 쓰는 도구에서 그 복잡도는 사용자가 얻는 것보다 큽니다.

항목을 열린 상태로 두면 이월에 아무 조작이 필요 없어 "급한 순간에 손이 덜 가야 한다"는 경험 원칙과 맞고, 날짜별 내역은 소요시간 기록이 붙을 때 자연히 생깁니다.

## Reconsider when

- 하루 단위로 목록 전체를 고정해 되돌아봐야 하는 요구가 생길 때
- 열린 항목이 계속 쌓여 오늘 목록이 아침에 판단하기 어려울 만큼 길어질 때

## Still-rejected alternatives

- 날짜별 목록 스냅샷을 만들고 미완료 항목을 다음 날로 복사하는 방식 — 날짜 전환 시점과 중복 처리를 따로 정해야 하고, 같은 항목이 여러 날에 걸쳐 존재하게 되어 소요시간을 어느 사본에 붙일지 다시 정해야 합니다. 과거 목록을 그대로 재현해야 하는 요구가 생기면 다시 검토합니다.
